# first-godot-game

Godot 4.7 2D 闪避游戏。玩家控制角色躲避从屏幕边缘出现的敌人，存活越久分数越高。

## v0.2.0 已实现

- 玩家移动（上下左右方向键）
- 敌人从屏幕四边随机生成
- 碰撞检测（碰即失败）
- 分数系统（存活时间 → 分数）
- 难度递增（每 10 秒加速敌人生成）
- 开始界面（标题 + 按钮）
- 失败界面（最终分数 + 重新开始）
- 数据版本 1

## v0.1.0 已实现

- 项目初始化
- 开发工作流搭建（AGENTS.md + PROJECT_GOAL.md）
- 自动化脚本（版本管理、通知、Issue处理）
- 数据版本 1，兼容初始存档

## 启动

使用 Godot 4.7 打开 project.godot，运行主场景 `res://scenes/Main.tscn`。

### 操作方式

- ↑ ↓ ← → 或 WASD：移动玩家
- 点击"Start Game"：开始游戏
- 点击"Restart"：重新开始

## 项目结构

```
first-godot-game/
├── scenes/
│   ├── Main.tscn          # 主游戏场景
│   ├── Player.tscn        # 玩家场景
│   └── Enemy.tscn         # 敌人场景
├── scripts/
│   ├── main.gd            # 游戏管理器（状态、分数、生成）
│   ├── player.gd          # 玩家移动与碰撞
│   ├── enemy.gd           # 敌人移动与边界清理
│   └── game_over.gd       # 失败界面逻辑
├── assets/
│   ├── sprites/           # 图片资源（占位）
│   └── audio/             # 音频资源（占位）
├── ui/
│   └── GameOver.tscn      # 失败界面
├── AGENTS.md              # 工作规则
├── PROJECT_GOAL.md        # 产品上下文
├── README.md              # 发布说明
└── .omo/                  # 自动化脚本
```

## 跨环境继续开发

完整产品上下文、已完成版本和持续开发规则保存在 PROJECT_GOAL.md，
AGENTS.md 会要求新环境在修改前读取该文件。换电脑后克隆仓库即可恢复开发上下文。

每轮开发还会检查仓库的开放 GitHub Issues：可执行的玩家建议会先回复纳入版本，
完成发布后再回复提交、标签和上线状态并关闭；需要补充信息的建议会回复问题并保持开放。

Issue 处理结果同时写入 PROJECT_GOAL.md 和本文件（双写），确保换环境后仍可追踪。
